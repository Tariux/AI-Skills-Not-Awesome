# Handling Non-DONE Reports

**DONE_WITH_CONCERNS:** Implementer completed but flagged doubts. Read concerns. If about correctness/scope → address before review. If observations → note and proceed to review.

**NEEDS_CONTEXT:** Implementer needs missing info. Provide context and re-dispatch.

**BLOCKED:** Implementer cannot complete. Assess:
1. Context problem → more context, re-dispatch same model
2. Needs more reasoning → re-dispatch more capable model
3. Task too large → break into smaller pieces
4. Plan wrong → rule on correction, ledger it, re-dispatch with ruling

**Never ignore escalation or force retry without changes.** If implementer says stuck, something must change.
